Talk to it

This downloads the models to your browser and keeps them in Cache Storage. First load is about 1.3 GB (less if you have used the Listen player, which already caches Kokoro and the ONNX Runtime). It needs a microphone and a GPU (WebGPU) for voice replies.

Type instead

No microphone? Type a message and the LLM answers it, spoken by Kokoro. This skips the VAD, turn and ASR stages.

How it works

The pipeline is one direction, with a loop back for barge-in. Each stage runs in your browser on ONNX Runtime Web; the audio path, the voice-activity and turn state machines, and the sentence splitter are Rust compiled to WebAssembly.

Mic VAD Turn ASR LLM Kokoro

Barge-in: while Kokoro is speaking, the microphone stays open on a stricter threshold. If you start talking, playback stops at once, the speech engine is cancelled, the in-flight answer is discarded, and the state shows interrupted.

Caveats & sources

  • WebGPU is required for voice replies. Without it, the VAD, turn detector and ASR still run (on the WASM backend), but the language model is too slow on a single thread to be usable, so the page says so and offers the text fallback.
  • Echo. Your speaker's output re-enters the microphone. The page uses the browser's echo cancellation and a stricter VAD threshold while speaking, but headphones are more reliable for barge-in.
  • Size. About 1.3 GB on first load. It is stored in Cache Storage, which has a quota on some browsers (notably Safari); the page tells you before it downloads.
  • Latency. The per-stage numbers are measured in your browser, not a fixed target. They depend on your GPU.

Models (all fetched from public Hugging Face repositories at runtime, nothing committed to this site): Silero VAD v5, Smart Turn v3.2, Moonshine base (ASR), LFM2.5-1.2B-Instruct (LLM), and Kokoro-82M (the site's shared Listen engine). The ONNX Runtime is the site's shared pinned loader.
