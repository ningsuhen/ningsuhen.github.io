The question

Can Spark-X2.6-4B replace Brev's current 4B generative tier (FrogNano / Qwen3.5) as the second-opinion classifier?

Status

Complete. Verdict: reject — no quality win, higher cost, and no shipping path on the current ONNX-WebGPU runtime.

How to read it

Accuracy is the headline. Latency numbers are a CPU-bound llama.cpp proxy, not the shipped WebGPU path — use them only for relative comparison across models.

Method

Three 4B models — Spark-X2.6-4B, Qwen3.5-4B, and FrogNano-4B — were each served as Q4_K_M GGUF via llama.cpp (b11889) on an Apple M4 Max and run over the same 1,960-row H5 test set (real customer-support messages, 196 intents). The arm is rules: a 196-rule system prompt (~18,800 tokens) with a ~4-token completion asking for a category key. Temperature 0, max_tokens 32, thinking disabled. Two recorded baselines are included for reference: Qwen3-4B-Instruct-2507 (RTX 4060, the original baseline) and Qwen3.8-27B (the teacher).

H5 test set
1,960 sealed customer-support messages across 196 intents. The same rows the original baseline was scored on.
rules arm
The hardest of the four harness arms: 196 category rules in the system prompt, ~18,800 tokens in, ~4 tokens out. A conservative proxy for the product's real ~12-category second-opinion prompt.
Q4_K_M
The quantization Brev ships. Matching the baseline's quant keeps the only variable the model itself.
Second opinion
The product role of the 4B tier: laya (the router) decides, and the 4B re-classifies the small fraction of messages laya is uncertain about (~6% of traffic).

All three 4B models land in the 83.9–84.6% band. Spark's 0.25-point lead over Qwen3.5 and 0.7-point lead over FrogNano are within noise on 1,960 rows. None approaches the 27B teacher at 90.4% — the 4B tiers leave roughly 5.7 points of headroom on the table. Spark is also the largest file (3.30 GB vs 2.55–2.61 GB for the current tiers, ~28% bigger), slower to decode on this runtime (p50 757 ms vs 296–399 ms), and its mean prompt is 1,273 tokens longer because the 196 rules render longer under Spark's 131k-vocab tokenizer.

Caveats

Read this first

Latency is llama.cpp on an Apple M4 Max, CPU-bound — a relative proxy across models, not the shipped WebGPU/ORT path. Do not compare these numbers to the recorded RTX 4060 baseline (159 ms p50) or to the model card's M5 Pro Metal figures.
  • Fit blocker (decisive). No ONNX q4f16 / WebGPU build of Spark exists, and onnxruntime-genai has no spark2_5 model builder. Shipping it means writing a new builder plus WebGPU EP validation — and likely hitting the same graph-size buffer-aliasing bug that PersonaPlex-7B hit.
  • Conservative proxy. The rules arm (196 rules, ~20k tokens) is harder than the product's real second-opinion prompt (~12 categories). A model that ties here would likely tie or do slightly better in production — the gap would be even smaller.
  • Card benchmarks don't transfer. Spark's model card reports a 63.3 aggregate (thinking mode, agentic/coding/math/long-context). Those numbers do not transfer to a no-thinking, 4-token classification task — the local run settles that.
  • Single runtime. All three 4B models ran on the same llama.cpp build and host. The relative comparison is fair, but absolute latency is not representative of the shipped ONNX-WebGPU path.
