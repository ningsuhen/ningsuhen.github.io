Research · design system

Research Design System · created 2026-10-24 · updated 2026-10-24

Every research report, analysis page and exported artifact uses this. It is the ningsuhen.github.io theme: same palette, radius, type and width, light by default with dark support.

Use it

<link rel="stylesheet" href="/design-system/research.css">
<html lang="en" data-theme="light">  <body class="rd-body">
  <main class="rd-container rd-prose"> ... </main>

Self-contained exports: inline the file's contents in a <style> tag instead of linking, and paste the page's lucide-sprite block (see Icons). Canonical source: public/design-system/research.css in the site repo. Everything is prefixed rd-, and type styles apply only inside .rd-prose, so it can't fight a report's own CSS.

Width

Default is the main site's content column: --rd-content-width: 54.5rem (872px, measured on the live site at a 1440px viewport; the site page is 75rem). That is .rd-container. Use .rd-container--wide (the full 75rem site page width) only when the content needs it: wide charts, dense tables, dashboards. Tables scroll inside their wrapper and never widen the page.

Theme contract

Light is the default and ignores the OS setting. Dark is <html data-theme="dark"> (or class="dark"). The site navbar is injected into every standalone page at build time; it reads and writes localStorage "theme" and sets data-theme for you, so a report needs no toggle of its own. Never read the OS preference to pick a theme. Use only the --rd-* variables for color so both modes work.

Icons (Lucide)

Icons are Lucide outlines, the site's icon language. Draw one with <svg class="rd-icon" aria-hidden="true"><use href="#i-file-text"/></svg>. The class sets the size (1.25em), stroke (currentColor, width 2, round caps and joins) and no fill, so an icon always matches the text beside it. Icons are never images and never a font.

Self-contained pages make no icon request: each page inlines only the symbols it uses, between the lucide-sprite markers. public/design-system/lucide-sprite.svg holds the union, for external reference.

To add an icon: reference #i-<name> (the name from lucide.dev) in the page, then run pnpm build or node scripts/build-lucide-sprite.mjs. The script reads @iconify-json/lucide, fails on an unknown name, and rewrites the markers. Nothing is hand-copied.

Experiment navbar

The in-page navigation for experiments and reports. It is rd-expnav, the live bar at the top of this page. It is full width and sticky at top: 0. The site bar above it is 56px and not sticky, so the two never overlap, and the nav never covers content it has not scrolled past. The section in view is highlighted (.is-active, aria-current) by a 20-line scroll-spy script with no dependencies. Smooth scrolling is on only when reduced motion is not requested. On a phone the links scroll sideways inside their own track, so the page never overflows. Links are plain anchors: they are keyboard reachable and show a focus ring.

<nav class="rd-expnav" aria-label="Sections">
<a href="#summary" class="is-active"><svg class="rd-icon" aria-hidden="true"><use href="#i-file-text"/></svg>Summary</a>
<a href="#method"><svg class="rd-icon" aria-hidden="true"><use href="#i-flask-conical"/></svg>Method</a>
</nav>

Put the nav directly under <body>, before <main>, so it spans the page. Each link targets a section header, <header class="rd-section__head" id="method">. The template has the nav and the script ready to copy.

Scientific writing

Everything a paper needs, prefixed rd-, with automatic numbering for equations, figures, tables and theorems. Math is KaTeX (pinned 0.16.27). In Markdown posts use $…$ inline and $…$ for display, and escape a literal dollar sign as \$ (an unescaped $5 … $7 is parsed as a formula). In standalone HTML, pre-render with katex.renderToString at build time and link katex.min.css, so the page needs no JavaScript for math.

Checklist for a new report

  • Math, citations, numbered equations and theorems follow the Scientific writing section; escape literal $ in Markdown.
  • Link or inline research.css; body rd-body, content in rd-container (wide only if justified, and say why in a comment).
  • Experiment pages: the sticky rd-expnav directly under <body>, one link per rd-section__head with an id, and the scroll-spy script from the template.
  • Icons: Lucide only, as #i-<name>, with the page inside the lucide-sprite markers (run node scripts/build-lucide-sprite.mjs).
  • Title and page heading carry created YYYY-MM-DD · updated YYYY-MM-DD.
  • Colors only via --rd-*; charts use the sequential or categorical palette.
  • No iframes; no dependence on a host runtime; navigation that users trigger creates history entries.
  • Caveats and unvalidated results are stated on the page, not buried.
  • Check both themes and a 375px viewport before publishing.
